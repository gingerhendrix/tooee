---
title: Launch apps from TypeScript
description: Call launch() from @tooee/choose, @tooee/ask, and @tooee/view in a Bun script and use what comes back.
---

```ts title="release.ts"
import { launch as launchAsk } from "@tooee/ask";
import { createStaticProvider, launch as launchChoose } from "@tooee/choose";
import { launch as launchView } from "@tooee/view";

const level = await launchChoose({
  contentProvider: createStaticProvider([{ text: "patch" }, { text: "minor" }, { text: "major" }]),
  options: { prompt: "Release type" },
});
if (level === null) {
  process.exit(1);
}

const notes = await launchAsk({ prompt: "Release notes:", multiline: true });
if (notes === null) {
  process.exit(1);
}

await launchView({
  contentProvider: {
    load: () => ({
      format: "markdown",
      markdown: `# ${level.items[0].text} release\n\n${notes}`,
      title: "Preview",
    }),
  },
});
```

Run it with `bun release.ts`. Each `launch()` opens one screen, waits until the session ends, restores the terminal, and resolves. The value depends on the app:

| Package         | Resolves with                                               |
| --------------- | ----------------------------------------------------------- |
| `@tooee/choose` | `ChooseResult` with the picked `items`, or `null` on cancel |
| `@tooee/ask`    | The submitted text as a `string`, or `null` on cancel       |
| `@tooee/view`   | `void`, after the reader quits with `q` or `ctrl+c`         |

[Install](/docs/start/install) covers adding the packages to a project. The screen draws on stdout and uses the alternate screen, so text you write to stdout after the `await` appears in the normal terminal.

## Launch View

```ts title="view-changelog.ts"
import { createFileProvider, launch, launchDirectory } from "@tooee/view";

await launch({ contentProvider: createFileProvider("CHANGELOG.md") });
await launchDirectory({ dirPath: "docs" });
```

The first session opens the file. When the reader quits, the second session opens the directory view from [View files and pipes](/docs/cli/view#open-a-directory).

| Option               | Type                                | Meaning                                                                                                 |
| -------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `contentProvider`    | `ContentProvider`                   | Where the content comes from. See [View: content and providers](/docs/apps/view/content-and-providers). |
| `actions`            | `ActionDefinition[]`                | Commands added to the screen. See [View: actions and command context](/docs/apps/view/actions).         |
| `renderers`          | `Record<string, ContentRenderer>`   | Renderers for your own content formats. See [View: custom renderers](/docs/apps/view/custom-renderers). |
| `codeBlockRenderers` | `Record<string, CodeBlockRenderer>` | Renderers for fenced code blocks in markdown, keyed by the first word of the fence info string.         |

`launchDirectory` takes `dirPath` and `actions`.

The promise stays pending for the whole session. Work that must happen while the screen is open runs before the `await`.

View reads keys from the process stdin. When stdin is a pipe, the session ends as soon as the pipe closes, so `launch()` cannot show piped input in Tooee 0.9.0. [Run your own session](#run-your-own-session) shows the `stdinPolicy` option that reads keys from the terminal instead.

## Launch Ask

```ts title="commit-message.ts"
import { $ } from "bun";
import { launch } from "@tooee/ask";

const message = await launch({
  title: "Commit",
  prompt: "Commit message:",
  placeholder: "Summary line, then details",
  multiline: true,
});
if (message === null) {
  process.exit(1);
}
await $`git commit -m ${message}`;
```

| Option         | Type                      | Meaning                                                                |
| -------------- | ------------------------- | ---------------------------------------------------------------------- |
| `title`        | `string`                  | Title bar text. No title bar when omitted.                             |
| `prompt`       | `string`                  | Bold line above the editor.                                            |
| `placeholder`  | `string`                  | Muted text shown while the editor is empty.                            |
| `defaultValue` | `string`                  | Initial text. The cursor starts at its end.                            |
| `multiline`    | `boolean`                 | `true` gives a textarea, `false` a one-line input. Defaults to `true`. |
| `actions`      | `ActionDefinition[]`      | Commands added to the screen. See [Ask](/docs/apps/ask#add-actions).   |
| `onSubmit`     | `(value: string) => void` | Runs with the submitted text before the promise resolves.              |

Ask starts in insert mode. `Enter` submits a one-line input, `Shift+Enter` submits the multiline editor, and `Escape` switches to cursor mode where `q` cancels. The key table is on [Ask and Choose in shell scripts](/docs/cli/ask-and-choose#ask-for-text). [Ask](/docs/apps/ask) covers editing, actions, and the dialog form.

## Launch Choose

```ts title="switch-branch.ts"
import { $ } from "bun";
import { launch } from "@tooee/choose";
import type { ChooseItem } from "@tooee/choose";

const branchProvider = {
  async load(): Promise<ChooseItem[]> {
    const proc = Bun.spawn(["git", "branch", "--format=%(refname:short)"]);
    const text = await new Response(proc.stdout).text();
    return text
      .trim()
      .split("\n")
      .map((branch) => ({ text: branch }));
  },
};

const picked = await launch({
  contentProvider: branchProvider,
  options: { prompt: "Switch branch" },
});
if (picked === null) {
  process.exit(1);
}
await $`git switch ${picked.items[0].text}`;
```

| Option            | Type                    | Meaning                                                                    |
| ----------------- | ----------------------- | -------------------------------------------------------------------------- |
| `contentProvider` | `ChooseContentProvider` | An object whose `load()` returns `ChooseItem[]` or a promise of it.        |
| `options`         | `ChooseOptions`         | `title`, `prompt`, `placeholder`, `multi`, and `emptyMessage`.             |
| `actions`         | `ActionDefinition[]`    | Commands added to the screen. See [Choose](/docs/apps/choose#add-actions). |

The `launch()` options keep `title`, `prompt`, and the rest nested under `options`. The `Choose` component takes the same fields as flat props.

Choose starts in insert mode with the filter focused. `Enter` confirms, `Escape` switches to cursor mode, and `q` in cursor mode cancels. With `multi: true`, `Tab` toggles items and `items` holds every toggled item in toggle order. When stdin is a pipe, Choose reads keys from `/dev/tty`, so a script can take its list from the pipe with `createStdinChooseProvider()`. [Choose](/docs/apps/choose) covers items, filtering, and the dialog form.

## Run your own session

The three `launch()` functions call `runCliSession` from `@tooee/shell`. Call it yourself to open any Tooee component with the same lifecycle and resolve a value of your own type:

```tsx title="confirm-delete.tsx"
import { $ } from "bun";
import { useCommand } from "@tooee/commands";
import { runCliSession } from "@tooee/shell";
import type { ReactNode } from "react";

const Confirm = function Confirm({ onAnswer }: { onAnswer: (yes: boolean) => void }): ReactNode {
  useCommand({ handler: () => onAnswer(true), hotkey: "y", id: "yes", title: "Yes" });
  useCommand({ handler: () => onAnswer(false), hotkey: "n", id: "no", title: "No" });
  return <text content="Delete the dist folder? y / n" />;
};

const yes = await runCliSession<boolean>(({ resolve }) => <Confirm onAnswer={resolve} />);
if (yes === true) {
  await $`rm -rf dist`;
}
```

`runCliSession<T>(render, options)` calls `render` with `{ resolve, cancel }` and returns `T | null`. `resolve(value)` ends the session with the value. `cancel()`, `ctrl+c`, or a destroyed renderer ends it with `null`. The component tree needs the JSX options from [Install](/docs/start/install#set-the-jsx-options).

The second argument configures the session:

| Option           | Default     | Meaning                                                                                      |
| ---------------- | ----------- | -------------------------------------------------------------------------------------------- |
| `provider`       | `{}`        | Options for the Tooee provider tree: `initialMode`, `leader`, `config`, `sequenceTimeoutMs`. |
| `stdinPolicy`    | `"process"` | `"tty-if-piped"` reads keys from `/dev/tty` when process stdin is a pipe.                    |
| `exitOnCtrlC`    | `true`      | `ctrl+c` ends the process.                                                                   |
| `terminalHealth` | `true`      | When the key stream ends or closes, destroy the renderer and exit with code 0.               |
| `renderer`       | `{}`        | Extra options for OpenTUI's `createCliRenderer`, except `stdin` and `exitOnCtrlC`.           |

`stdinPolicy: "tty-if-piped"` is how Choose accepts a piped list. View does not set it, so use `runCliSession` to show piped input in View:

```tsx title="pipe-view.tsx"
import { runCliSession } from "@tooee/shell";
import { View, createStdinProvider } from "@tooee/view";

await runCliSession(() => <View contentProvider={createStdinProvider()} />, {
  stdinPolicy: "tty-if-piped",
});
```

```bash
git diff | bun pipe-view.tsx
```

Put `initialMode`, `leader`, `config`, and `sequenceTimeoutMs` under `provider`. Tooee 0.9 no longer accepts these settings at the top level.
